### 3.2 检查配置与数据合规

- **检查配置**：每个仓库要有项目检查配置（对应 C4.6「检查环境固定」），并纳入该仓库的任务卡
  `checks` 约定（`eval/tasks/README.md` §2）。
- **数据合规（P14）**：任务/仓库数据包来源与许可、脱敏、训练数据污染边界（`eval/tasks/README.md` §4）
  必须由负责人确认；未确认前不得进入真实运行。

### 3.3 预算、人员与模型

- **预算（P13）**：成本上限按 PREREG §5 执行（数值待负责人确认）；组合越多，总成本按组合数线性放大。
- **人员（P12）**：任务作者、范围评审者、两名盲评标注者 + 裁决者、**独立复现者**各自有人选。
- **模型（≥2）**：记录 `modelId`、`provider`、版本与实际参数；宿主不支持的参数写"不可控"
  （RUNBOOK §6），不得假装固定。

### 3.4 组合就绪判定（`b7-matrix.mjs` 的口径）

一个 repo × model 组合 **eligible** 当且仅当：

1. **环境就绪** = `environmentReady && offlineBuild`（离线构建属于 P10 环境准备）；
2. **检查配置就绪** = `checksConfig`。

不满足的项按输入字段名写入 `blockers`：`environment-not-ready` / `offline-build-not-ready` /
`checks-config-not-ready`。**样本量状态固定为 `pending-prereg`**——具体数值必须由 PREREG 按分层锁定，
工具不计算、不猜测、不编造。

## 4. 如何生成组合清单（`eval/b7-matrix.mjs`）

### 4.1 用法

```sh
node eval/b7-matrix.mjs --repos <repos.json> --models <models.json> \
     (--out <matrix.json> | --dry-run)
node eval/b7-matrix.mjs --self-test
```

- `--dry-run`：把矩阵打印到 stdout，**不写文件**；`--out`：写文件并在 stderr 打印一行摘要。
- 退出码：`0` 成功；`1` 预期外错误；`2` **用法/校验错误**（未知参数、缺参数、非法 JSON、未知字段、
  重复 id、空输入、非法枚举/类型）。
- 无依赖、只用 Node 内置模块；不访问网络/宿主，不执行任何运行。

### 4.2 输入 `repos.json`

数组，或 `{ "repos": [...] }`（对象形式不允许额外字段）。每个仓库条目：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `repoId` | string | 是 | `^[a-z0-9][a-z0-9._-]{1,63}$`，唯一 |
| `language` | enum | 是 | `java` / `typescript` / `python` |
| `stack` | string | 否 | 非空字符串（`maven` / `pnpm` / `pip` …） |
| `environmentReady` | boolean | 是 | P10 构建环境是否就绪（严格 true/false） |
| `checksConfig` | boolean | 是 | 项目检查配置是否就绪 |
| `offlineBuild` | boolean | 是 | 离线构建是否已验证 |
| `notes` | string | 否 | 非空字符串（例如 P10 证据路径） |

### 4.3 输入 `models.json`

数组，或 `{ "models": [...] }`（对象形式不允许额外字段）。每个模型条目：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `modelId` | string | 是 | `^[a-z0-9][a-z0-9._-]{1,63}$`，唯一 |
| `provider` | string | 是 | 非空字符串 |
| `notes` | string | 否 | 非空字符串 |

**所有未知字段一律拒绝**（不是在条目里"宽容忽略"）：拼错字段名会直接 exit 2，避免把准备状态写错却没发现。

### 4.4 输出矩阵

顶层字段：`schemaVersion: 1`、`generatedBy`、`generatedAt`、`preregLocked: false`、
`notes[]`（第一条明确"不是实验结果"）、`source`（输入路径）、
`targets`（`minRepos: 3` / `minModels: 2` 与是否满足）、`totalCombinations`、`eligibleCombinations`、
`blockedCombinations`、`repos[]`、`models[]`、`combos[]`。

每个组合行：

| 字段 | 说明 |
| --- | --- |
| `comboId` | `b7-<repo>-<model>`，唯一且确定 |
| `repo` / `model` | 输入 id |
| `environmentReady` | P10 环境就绪（含离线构建） |
| `checksReady` | 检查配置就绪 |
| `eligible` | `environmentReady && checksReady` |
| `blockers[]` | 未就绪项的字段名；**为空当且仅当 `eligible` 为 true** |
| `sampleSizeStatus` | 固定 `"pending-prereg"` |

生成规则：组合按 `(repo, model)` 稳定排序；同一输入重复生成，除 `generatedAt` 外逐字节一致；
`preregLocked` 恒为 `false`（本工具不修改 PREREG）。

### 4.5 例：合成夹具的真实 dry-run（**不是真实仓库清单**）

2026-11-07 用临时合成夹具（3 个 repo × 2 个模型，全部是占位值；Node `v22.19.0`，仓库根目录）执行：

```sh
node eval/b7-matrix.mjs --repos /tmp/b7-fixtures/repos.json \
     --models /tmp/b7-fixtures/models.json --dry-run
```

实测结果摘要（`exit 0`）：`totalCombinations=6`、`eligibleCombinations=0`、`blockedCombinations=6`、
`targets.reposMet=true`、`targets.modelsMet=true`；`dubbo` 两个组合的 blocker 为
`checks-config-not-ready`，`ts-project` / `py-project` 的组合三个 blocker 全中；所有
`sampleSizeStatus` 均为 `pending-prereg`。该夹具刻意按现状构造（Dubbo 环境部分就绪但无检查配置，
另两个仓库未准备），**只能证明工具行为，不代表任何真实仓库结论**。

### 4.6 自测

```sh

```

2026-11-07 实测（Node `v22.19.0`）：**`PASS: 36 assertions (b7-matrix self-test)`，exit 0**。覆盖：全就绪（3×2=6 组合全

## 5. 与 B5 / PREREG 的关系

```
B7 准备矩阵（本工具）        ← 只盘点组合是否具备开跑条件
   ↓ 每个 eligible 组合仍需：
P10 / B2 / 检查配置 / 数据合规 / 预算 / 人员   全部就绪
   ↓
PREREG 锁定（§6 样本量按 repo/model/类别分层；§9 锁定 seed 与版本；D-4/D-7 待负责人）
   ↓
eval/b5-plan.mjs 按分层生成 plan.json（seed 可复现、两组交错、20% 重复）
   ↓
试跑（每任务每组 3 次，估计波动与样本量）→ 正式运行 → 盲评/统计 → 独立复现（B7 后半）
```

- **矩阵不替代 plan**：`b5-plan.mjs` 决定每个分层内"先跑谁、跑多少"；本工具只决定"哪些组合够格进入
  计划"。二者输入不同，不能互相代替。
- **样本量不来自本工具**：矩阵里 `sampleSizeStatus` 恒为 `pending-prereg`；真实数值必须由 PREREG §6
  按分层锁定，试跑后填入（D-4）。
- **不合并分层**：跨仓库/模型的组合不得用总数代替各分层样本量（ROADMAP §B7、PREREG §6）。
- **范围待负责人**：第一轮是否只做单仓库、B7 多仓库何时进入，由 PREREG §10 **D-7** 决定；本文件只提供
  盘点工具，不擅自扩大第一轮范围。
