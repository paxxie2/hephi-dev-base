## 2. 证据来源（甲提供）

- **假设**：减少「为了通过而修改既有验收测试」被放行的风险，同时避免把所有既有测试默认当成不可修改。
- **合法用例**：需求本身要求修改受保护测试时，Worker 在某个验收项获得授权后可以继续。
- **开发集误拦率**：合法需求因清单过宽被拒的比例；Worker 反复申请扩大范围、或为绕开限制新增重复测试的频率。
- **副作用观察**：新增重复测试、验收项膨胀、审查成本；项目把清单扩大到全部既有测试时的表现。
- **项目能力证据**：宿主/插件能否读取清单、记录授权、在 ready 判定中引用授权记录。
- **证据缺口**：以上全部待甲提供；当前无开发集误拦率、无宿主能力验证、无真实授权记录。

## 3. 选项

| 选项 | 说明 | 风险/成本 |
| --- | --- | --- |
| A. 维持关闭（默认） | 不新增字段、不拦截；保持现有规则 | 无新增风险；关键验收资产仍可能被绕过 |
| B. 严格清单拦截 | 只保护显式清单；未授权修改/删除拒绝 | 清单遗漏会漏保护；清单过宽提高误拦率 |
| C. 清单内拦截 + 清单外修改只记录 | ROADMAP 候选：清单外删除仍拒绝、修改只记录 | 需要记录通道；审查者需理解记录 |
| D. 项目级扩大到全部既有测试 | 项目自选最严格模式 | 误拦率与副作用需单独测量 |

## 4. 影响

- 对 B 线指标：不直接改变 M1–M3 的统计口径；通过减少测试削弱间接影响交付质量与 G2。
- 对样本量/成本/可比性：不改变配对设计；可能增加审查/返工成本，需计入维护成本日志。
- 开发者摩擦：授权流程、清单维护；误拦会转化为人工介入。
- 失败语义：未授权拒绝必须可解释（指出资产与缺失授权）；不得静默降级为警告。
- 回滚：字段与拦截规则必须可关闭；回滚不影响既有运行记录。
