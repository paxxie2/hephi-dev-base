# C2 未覆盖改动的风险提示 — 决策模板

> 状态：**未批准（默认关闭）/ 待决**。本文件是模板，不是批准记录。
> 对应 ROADMAP-95 §5 C2（原 WP4.1）。执行 Agent 无权代批。

## 1. 决策标识

| 字段 | 值 |
| --- | --- |
| decisionId | `C2` |
| 事项 | 找出未被现有验收测试执行到的可执行改动，作为风险提示写入改动摘要；**不承担**防止无关重构的职责（被执行到不等于有断言，也不等于改动必要） |
| 形式 | 项目提供的检查脚本（附 Java/Node 示例），赫菲不解析覆盖率 |
| 是否拦截 | 否（默认提示；是否作为必需检查由项目决定） |
| 依赖前置 | 项目检查脚本；改动摘要字段；覆盖率/执行轨迹数据来源 |
| 当前状态 | `未批准（默认关闭）` |
| 适用轮次 | 未定（负责人批准时填写） |

## 2. 证据来源（甲提供）

- **假设**：让审查者看到「没被现有验收测试执行到的可执行改动」，降低漏检风险。
- **合法用例**：正常需求改动全部被现有测试覆盖时，提示应为空且流程不中断。
- **开发集误拦率**：提示误报比例；被标为「无关改动」的运行中，有多少被提示命中。
- **副作用观察**：提示对审查时间的影响、Worker 为消除提示而新增测试的行为。
- **项目能力证据**：检查脚本可运行、结果格式稳定、与任务卡 hiddenTest/checks 的边界清晰。
- **证据缺口**：以上全部待甲提供；当前无真实覆盖率/执行轨迹数据，也未跑开发集。

## 3. 选项

| 选项 | 说明 | 风险/成本 |
| --- | --- | --- |
| A. 维持关闭（默认） | 不生成提示 | 无新增风险；漏检风险仍在 |
| B. 仅提示 | 写入改动摘要，不阻塞 | 提示噪音；审查者可能忽略 |
| C. 项目可选为必需检查 | 项目明确要求时作为验收检查 | 误报会直接阻塞合法交付 |

## 4. 影响

- 对 B 线指标：不改变主指标计算；只影响审查材料完整度。
- 对样本量/成本/可比性：增加检查耗时；不得把提示混入 M2/M3 的盲评标签。
- 开发者摩擦：提示噪音；需要项目脚本维护。
- 失败语义：提示失败不等于运行失败；不得把「提示命中」机械判定为无关改动。
- 回滚：提示字段可移除；不影响已有记录。
