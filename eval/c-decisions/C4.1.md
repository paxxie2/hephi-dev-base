# C4.1 先复现再修 — 决策模板

> 状态：**未批准（默认关闭）/ 待决**。本文件是模板，不是批准记录。
> 对应 ROADMAP-95 §5 C4.1（原 WP2.6）。执行 Agent 无权代批。

## 1. 决策标识

| 字段 | 值 |
| --- | --- |
| decisionId | `C4.1` |
| 事项 | 修 bug 类任务先复现失败再修复；**行为保持重构、纯新增功能明确跳过**（重构任务不要求先失败） |
| 形式 | Skill（提示/流程要求） |
| 是否拦截 | 否 |
| 依赖前置 | 任务类别字段（`category`）；可复现的失败证据格式 |
| 当前状态 | `未批准（默认关闭）` |
| 适用轮次 | 未定（负责人批准时填写） |

## 2. 证据来源（甲提供）

- **假设**：减少「没定位根因就改」的修复，提升实现无缺陷率（G2）。
- **合法用例**：defect-fix 任务按复现步骤得到既存失败并保留输出；重构/新增功能任务跳过且不被判违规。
- **开发集误拦率**：不适用拦截；需测「要求复现」对非 bug 任务的误伤与额外成本。
- **副作用观察**：复现步骤耗时、Worker 为满足要求而伪造失败输出的风险（必须禁止）。
- **项目能力证据**：任务卡是否提供可执行复现命令 / hiddenTest；失败输出如何归档。
- **证据缺口**：以上全部待甲提供；当前无开发集数据、无复现步骤样例。

## 3. 选项

| 选项 | 说明 | 风险/成本 |
| --- | --- | --- |
| A. 维持关闭（默认） | 不要求先复现 | 无新增风险；根因定位质量无约束 |
| B. Skill 要求（仅 defect-fix） | 按类别触发；重构/新增跳过 | 需要类别可靠；增加前置时间 |
| C. 仅提示 | Skill 建议，不作要求 | 采纳率不可控 |

## 4. 影响

- 对 B 线指标：可能影响 G2/G1；不直接改变 M1–M3。
- 对样本量/成本/可比性：增加每次运行前置时间，需计入成本；类别定义必须与 PREREG 分层一致。
- 开发者摩擦：多一步复现；重构任务若被误要求会降低效率。
- 失败语义：无法复现不等于任务失败；应按固定格式记录「未复现」并继续或报告，不得伪造。
- 回滚：Skill 提示可移除；不影响已有记录。
