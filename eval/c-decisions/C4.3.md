## 2. 证据来源（甲提供）

- **假设**：减少意外文件与调试残留进入交付，改善 G2/G3 与盲评印象。
- **合法用例**：正常任务按清单自查后提交，且不产生额外阻塞。
- **开发集误拦率**：不适用拦截；需测自查带来的额外时间/token 与对交付质量的影响。
- **副作用观察**：Worker 自查变成走过场（只打印不检查）的风险；额外轮次。
- **项目能力证据**：Skill 可修改的范围；审查者能否看到自查记录。
- **证据缺口**：以上全部待甲提供；当前无开发集数据。

## 3. 选项

| 选项 | 说明 | 风险/成本 |
| --- | --- | --- |
| A. 维持关闭（默认） | 不要求自查 | 无新增风险；意外文件依赖现有检查 |
| B. Skill 要求固定清单 | 每次提交前按清单自查 | 增加成本；可能形式化 |
| C. 仅提示 | Skill 建议 | 采纳率不可控 |

## 4. 影响

- 对 B 线指标：不直接改变 M1–M3；可能间接影响 G2/G3。
- 对样本量/成本/可比性：增加运行成本；需计入 D4。
- 开发者摩擦：低；主要是额外轮次。
- 失败语义：自查发现问题应修正而非报告失败；不得把自查记录当作质量结论。
- 回滚：Skill 提示可移除。
