## 2. 证据来源（甲提供）

- **假设**：提高交付可审查性与缺陷定位能力，改善 G2/G3。
- **合法用例**：一个验收项一个（或少数几个）提交，检查通过后继续；不产生额外阻塞。
- **开发集误拦率**：不适用拦截；需测提交次数增加带来的成本与审查负担。
- **副作用观察**：过细提交造成历史噪音；提交与验收项对不上；与宿主/仓库提交规范冲突。
- **项目能力证据**：验收项在任务卡中的结构；审查者如何看到提交与验收项映射。
- **证据缺口**：以上全部待甲提供；当前无开发集数据。

## 3. 选项

| 选项 | 说明 | 风险/成本 |
| --- | --- | --- |
| A. 维持关闭（默认） | 不要求小步提交 | 无新增风险；审查粒度依赖 Worker 自觉 |
| B. Skill 要求（建议粒度） | 按验收项小步提交 | 增加提交次数与时间 |
| C. 仅提示 | 建议而非要求 | 采纳率不可控 |

## 4. 影响

- 对 B 线指标：不直接改变 M1–M3；可能间接影响 G3。
- 对样本量/成本/可比性：可能增加运行时间；需计入成本。
- 开发者摩擦：提交历史变长；需要验收项清晰。
- 失败语义：提交粒度不是验收条件；不得因粒度判断运行失败。
- 回滚：Skill 提示可移除。
