## 2. 证据来源（甲提供）

- **假设**：小任务更容易验收、盲评与复现，改善 G1/G2/G3 与样本利用率。
- **合法用例**：一个大 Issue 按模板拆成多个可独立运行的任务卡，且不丢失验收项。
- **开发集误拦率**：不适用拦截；需观察拆小对任务难度分层与样本量的影响。
- **副作用观察**：拆分后任务数膨胀、跨任务耦合、验收项粒度不一致；是否影响 D2 分层口径。
- **项目能力证据**：Issue 模板可否修改；任务卡 schema 是否支持父/子任务关系。
- **证据缺口**：以上全部待甲提供；当前任务集只有 2 个准备任务，无拆小数据。

## 3. 选项

| 选项 | 说明 | 风险/成本 |
| --- | --- | --- |
| A. 维持关闭（默认） | 不做拆小引导 | 无新增风险；大任务验收困难 |
| B. 模板建议拆分 | Issue 模板加入拆分建议 | 采纳率不可控；不改变任务卡 |
| C. 任务集准入要求 | 拆小作为任务卡准入条件 | 增加任务准备成本；改变类别分布 |

## 4. 影响

- 对 B 线指标：不直接改变统计量；影响任务难度分层与样本量估计。
- 对样本量/成本/可比性：拆分改变任务计数与分层，必须与 PREREG 样本量口径一致。
- 开发者摩擦：任务准备成本；拆分质量依赖人工判断。
- 失败语义：拆小规则不是验收条件；不得因未拆分判任务无效。
- 回滚：模板改动可回滚；既有任务保留。
