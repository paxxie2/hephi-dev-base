# 工作线 C 决策模板（C1–C5）

本目录是 ROADMAP-95 §5「工作线 C：能力增强」的**逐项决策模板**，只准备决策与证据格式，
**不启用任何功能、不锁定任何参数、不产生实验结论**。

> 状态：全部条目 **未批准（默认关闭）/ 待决**。基线 `main=bc21caca316d6032ebcc3d2bc6387c38e0a3579c`。
> 执行 Agent 无权代批；负责人（用户）书面批准前，任何条目都不得写成「已启用 / 已通过 / 已验证」。

## 1. 与其它文件的关系

- 本目录**不替代** `eval/PREREG.md` 与 `eval/decisions-draft.md`。PREREG 的 D-1..D-10 是 B 线
  实验口径决策；本目录的 C 条目是「是否实现/启用增强机制」的前置决策，二者编号、批准记录各自独立。
- 若某项 C 决策改变 B 线实验口径（例如 C3 改变组别定义、C4.5 改变失败计数口径），批准后必须
  同步更新 `eval/PREREG.md` 相应章节并重新锁定；否则不得进入正式分析。
- `eval/prereg-lock.mjs` 只扫描 PREREG 与 decisions-draft 的未决标记；本目录不是 PREREG 锁的输入。
- ROADMAP-95 §5 的统一规则：**每项功能先写明假设（它要改善哪个指标）、配一条合法用例、在开发集
  上测误拦率，再决定**：作为拦截规则采用 / 降为提示 / 放弃。功能本身不加分；只有在工作线 B 的
  新一轮评估中证明收益才影响 D2、D4 的档位。

## 2. 状态约定

| 状态 | 含义 | 允许出现的表述 |
| --- | --- | --- |
| `未批准（默认关闭）` | 模板初始状态；功能不实现/不启用 | 「待决」「默认关闭」「候选」 |
| `approve` | 负责人书面批准，按模板 §5 记录 | 「已批准（负责人/日期）」，但仍不等于已通过验证 |
| `reject` | 负责人拒绝，保留证据 | 「已拒绝」 |
| `defer` | 暂缓，等待甲提供证据或前置能力 | 「暂缓」 |

- 批准必须由**实验负责人（用户）**做出，且必须包含：决定、理由、日期、批准人、适用轮次/版本、
  命中的甲提供证据引用。缺失任一项的「口头/上下文里说过」不算批准。
- 批准 ≠ 通过验证。是否真的改善指标、误拦率是否可接受，仍须按 ROADMAP 统一规则在开发集上验证。
- 证据来源「甲」：需求/任务提供方（甲方）提供的合法用例、开发集误拦率、副作用观察和宿主能力证据。
  **当前全部为待补**；不得用模型自判、静态推演或未跑通的环境冒充。

## 4. 每份模板的固定结构

1. **决策标识**：decisionId、事项、形式、是否拦截、依赖前置、当前状态、适用轮次；
2. **证据来源（甲提供）**：假设、合法用例、开发集误拦率、副作用观察、宿主/项目能力证据、证据缺口；
3. **选项**：至少包含「维持关闭（默认）」与 ROADMAP 候选方案；
4. **影响**：对 B 线指标、样本量/成本/可比性、开发者摩擦、失败语义与回滚；
5. **负责人批准位**：固定字段的批准槽（当前为空）；
6. **默认（未批准时）**：关闭/不实现的明确行为；
7. **批准记录格式**：负责人批准的固定格式（追加到本模板 §5，并同步相关文件）。

## 5. 禁止事项

- 不得预填「已启用 / 已批准 / 已验证 / 已通过」；
- 不得把 ROADMAP 候选方案当成本次批准的参数；
- 不得把未经甲提供的证据（含模型自判、静态推演、未跑通环境）写成证据；
- 不得为了追求「功能齐全」而跳过合法用例与误拦率；
- 不得在未批准前修改任务卡字段、宿主配置、Skill 或插件实现。
