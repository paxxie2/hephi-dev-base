## 3. 三个阻塞项的改法（评审重点看这里）

### F2 → R1：P5 合同哈希顺序敏感
- `activation.ts`：`ACTIVATION_VERSION = 2`；新增 `canonicalize()`（递归排序对象 key、数组保序）+ `canonicalPayload()`，`contractHash()` 改为对规范化 JSON 做 sha256。
- 兼容：`version: 1` 或**没有 version 字段**的旧合同仍用 `legacyPayload()`（原始 `JSON.stringify` 键序）计算并读取，只读；未知版本先验 hash 再拒绝，错误信息明确要求重签合同而不是手改 hash。
- `supportedVersion()`：`1`/`undefined`/`2` 接受，其它值报 `unsupported HEPHI activation version: X; re-prepare a new contract with the current plugin instead of editing the stored hash`。
- 验证：`activation.test.ts` 30 passed，含 R1-T01–T12；R1-T12 的固定夹具期望值 `sha256:14756a3e…c50` 用**独立 Python 实现**复算一致。

### F3 → R2：P2 从脏工作树构建
- `tsdown.config.ts` 改成懒加载 `defineConfig((_inlineConfig, _context) => ...)`，构建时才调 `resolveBuildCommit()`：
  - 有 git：`git rev-parse HEAD` 取完整 SHA，`git status --porcelain`（含已跟踪/暂存/未跟踪）非空则抛 `refusing to build from a dirty working tree: …`；
  - 无 git（源码归档）：`HEPHI_BUILD_COMMIT` 必须是完整 40 位十六进制，否则拒绝；
  - 不再有 `-dirty` 后缀发布路径。
- 验证：`build-commit.test.ts` 9 passed（R2-T01–T08 + 配置惰性）；真实脏树 `pnpm build` exit 1（原文见验证记录）。

### F1 → R3：P8 不可变发布 / 自动回滚 / 全健康
`scripts/host/deploy-hephi.sh` 重写，脚本头部写死 8 条不变量。关键点：
1. **构建与实载分离**：`git archive <sha> | tar -x` 到 `releases/.build-<sha>-XXXX`，`HEPHI_BUILD_COMMIT=<sha> pnpm install --frozen-lockfile && pnpm check`，绝不在实载 `$hephi/lib` 上构建。
2. **不可变发布**：`releases/<sha>/` 已存在即拒绝（非零退出，不 `rm -rf`）；新发布先写 `.incoming-<sha>-<pid>` → 校验 → 单次原子 `mv`；`meta.json` 记 `formatVersion/pluginCommit/sourceTree/entrySha256/builtAt/buildCommand/hostVersion/source`。
3. **原子指针**：`$hephi/lib` 从普通目录迁移为 symlink，后续用临时 symlink + `fs.renameSync` 单次替换，不先删后建。
4. **全健康门禁**：显式 10 项 `runtime relay notice launch delivery assessment reply evals models github`，任一 `starting`/`error`/缺失/超时都算失败（旧脚本只看 `runtime`，历史记录 `deploy-20261107T054720.json` 里 `github=starting` 仍判成功，该事实已原样保留在文档）。
5. **自动回滚**：切换后重启或健康失败 → 恢复 previous 指针 → 重启 → 全量健康复检 → 写记录 → 非零退出；连恢复也失败则 `failed-twice` 保持 `paused=true` 交人工。
6. **drain**：`running`/`queued` 必须为 0；`startupReservations/effects/jobs/subagents/unknown` 必须存在且为 0，缺失按 `unverified` 拒绝（不按 0）；open ticket > 0 拒绝；`--allow-open-tickets` 已删除，传入按未知参数 exit 2。
7. `--host-version` 必填单行值；`--rollback` 必须显式 `--target`；dry-run 只读检查不切指针不重启。
8. 成功退出也**不**自动恢复派发；P8 真实验收因宿主无实载 commit 回读入口保持 unverified。

## 6. 已知坑 / 实现细节（便于判断质量）

- **假宿主套件的根因坑**：最初把 HTTP 假宿主与 `spawnSync` 部署放同一进程，`spawnSync` 阻塞事件循环导致假宿主无法应答，每次部署硬等 120s 超时；改为异步 `spawn` + 等 `start.log` 递增后修复（整套 50s）。
- **R2 与 R5 的耦合**：R2 之后 dirty 树构建直接失败，所以 `pnpm check` 必须在**已提交干净树**上跑；本轮先提交 docs 再复跑，未使用任何环境变量绕过。
- **同 SHA 重发**：语义定为"目标 = 当前实载 SHA 时拒绝"（空操作），而不是"任何已存在 release 都拒绝"——否则 A→B→A 正常切换会被误伤。
- **rollback 需要显式 target**，不接受"最近快照"这种随时间变化的目标。
- **健康门禁 10 项**来自实验 B 的真实服务表；`github=starting` 历史事实未篡改。
- 时点链：175（G2）→176（初检）→180（S6/S7, main@5efd708）→192（R1）→201（R1+R2）→**202（R3）**，历史数字不回改。
