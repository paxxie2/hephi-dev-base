## Implementation consequences

- `hephi_check` only accepts `checkId`; the command, argv, cwd, parser, expectation, report paths and target cases come from the contract's frozen `verification.checks`. Checks declare `kind: "build"` (exit code allowed) or `kind: "test"` (real JUnit case evidence required). Reproduction also freezes an `expectedFailure` type/message signature.
- The internal bash call is dispatched through `agent.ctx.tools.execute` with the runner-generated `callId`, `parent: outer.token`, `rootCallId: outer.callId`, the same `agent`, and a fixed `bash` invocation. The run record stores that exact same inner call id; it is not generated twice. Admission compares the complete closure-owned identity (`callId`, parent token, root call id, agent, command, cwd), never just the tool name.
- Nested `tools.execute` calls do **not** produce their own Session events. The run record stores only the outer `hephi_check` call id, the inner bash call id, and the native Job id where one exists. No event UUID is claimed.
- Unknown bash result kinds, invalid fields or non-terminal Jobs are rejected. The contract deadline and outer abort stay active for the whole lifecycle; a promoted/background Job is polled through `ctx.jobs` across repeated wait windows until it reaches a terminal state or the remaining contract budget expires. A timeout/cancel kills it and requires a confirmed terminal status before admission is reopened. If settlement cannot be confirmed, the run record persists an `execution-unconfirmed` fact with the native Job id; a fresh check or ready rejects until that exact Job is observed terminal or an operator handles it. A remount alone does not clear it.
- Job `detail` is a producer string, not a typed exit code. This implementation accepts only the documented `exit code: <integer>` form and reports a blocked result for any other detail. That is a real API gap; it does not guess an exit code from output text.
- Check admission audits the complete descendant Agent tree (not just direct children) and every descendant's native Jobs. A running/unknown descendant or Job blocks the check. Parent-Session background Jobs are deliberately not inspected: an old preview server cannot be reliably distinguished from a write job through the public registry, so previews are never killed and are not treated as check blockers. This is a known concurrency limitation, not absolute isolation. Check admission also drains tracked in-flight modification/delegation calls.
- A test-injected native runner is marked `executor.source: "diagnostic"` in the run record and is rejected by ready. The default `agent.ctx.tools.execute` path is marked `native`. Tests use the native entry with a fake host tool result for wiring; they are not a real DSH host end-to-end run. The compiled fixture additionally loads the built `lib` artifact through rc.5 `ToolRuntime` and exercises compiled `hephi_check` -> saved evidence -> compiled ready, then changes the loaded bundle on disk and expects ready rejection. It registers a minimal local bash adapter because that fixture composition does not mount the real DSH shell tool; the adapter is test-only. The fixture uses a temporary mixed dependency directory and is not deployment.
- The executor identity is captured once when the identity module loads. In a bundle it hashes the executing bundle; in the source test environment it hashes a manifest of the complete executor source files. Ready recomputes the recorded identity; replacing the on-disk bundle/source after the run fails the check instead of being mistaken for a new executing version.
- `ready` reads the latest saved run for each required check, rechecks contract/check hash, HEAD/patch/changed paths, output/report hashes and re-parses the snapshotted JUnit reports. It never calls a project test command.
- Check entry rejects every legacy `status: running` record. If that record has a recoverable native Job id, the controller confirms terminal status and marks the old run blocked/recovered; otherwise it persists an `execution-unconfirmed` fact. A newer pass cannot mask an old running/unresolved record in ready.
